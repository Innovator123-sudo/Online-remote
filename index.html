01 Discover TVs on your network

Scans the same Wi-Fi via the local server's SSDP and shows only real TVs. Add your TV IP manually too. Your PC running node server.js does the discovery + ADB; open its LAN URL from any phone on the same Wi-Fi.

Why this must run on your home Wi-Fi ℹ️

ADB and SSDP only work between devices on the same local network. A cloud server is not on your Wi-Fi, so it can never reach your TV's private IP (e.g. 192.168.1.84). Instead, run node server.js on your PC — it becomes the bridge — then open http://<PC-LAN-IP>:5000 from your phone to control the TV.

02 One-hand gesture → D-Pad

Open palm (or index finger) position is mapped to UP / DOWN / LEFT / RIGHT. Hold your hand steady in a zone for 2 seconds (~hold-to-click) and the D-Pad command fires — no more accidental fast clicks. CENTER is intentionally idle — it’s the keypad/dwell zone where no D-Pad event fires (avoid accidental inputs while typing/drawing).

How it decides

  1. 1 hand + ≤1 finger extended → navigation mode. Palm centroid mapped to zones.
  2. 2 fingers (index + middle) extended → drawing mode (see next section). Navigation paused.
  3. Hit UP/DOWN/LEFT/RIGHT fires once per cooldown. Staying in zone does not spam.
  4. CENTER never fires a D-Pad command — use it as rest / to access on-screen keypad.

🚀 How it works (nothing to set up)

The bridge starts automatically with Windows on your home PC. Every device on the same Wi-Fi just opens its one-tap link (see Network Scan → 📱 / ☁️ links → Copy) — the page then scans, validates the TV, pairs and connects all by itself, and remembers it for next time.

PC:     bridge auto-starts at logon (done automatically)
Phone:  open the 📱 or ☁️ link (same Wi-Fi) → remote is already connected

Control depth depends on the TV: Android TV with Network debugging → full D-Pad remote. Chromecast → play/pause, quit-to-home, volume. Same Wi-Fi only — a browser hard limit, not a bug.
